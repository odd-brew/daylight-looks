# Learning

## 2026-11-22 — ODB-156, no public frame-style setter

Daylight's plugin guide (Frame styles, API 1.8) and `API.lua` `View.AddFrameStyle` (around line 1450) are how a plugin adds a style. The style then shows up in Daylight's own Frame style menus. The saved key is `Plugin:key`, for example `Looks:lintel`.

There is no public call that selects the current style. `API.GetSetting` is documented as read-only, and it is not a frame-style setter. `me.Override` changes a setting only for a while and is not saved. The write that actually picks a style is private: `ns.SetStyle` in `DaylightUI_UnitFrames/Units.lua` (around line 150), which calls `DUI:Set("UnitFrames", path, value)`. The guide says only `DaylightUI.API` is promised.

Looks therefore registers Lintel, Sill and Stamp, and does not call `Set` on UnitFrames. `/looks lintel` says to pick Lintel in the Frame style menu. Restore says to pick Daylight there. `/looks` with no extra word reads the player frame through `API.GetUnitFrame("player")` and `API.Parts`, whose `style` field the guide documents (`"daylight"`, `"ribbon"`, or `"Looks:lintel"`).

Stamp's ring is 0.35. Ribbon's documented ring is 0.56. Sizes are left out so Daylight fills in its own heights. The signed-off mock draws Stamp's bar a little shorter so the picture reads apart from Ribbon. That trim is a picture, not a `sizes` entry, until someone asks for it in the style itself.

## 2026-11-22 — ODB-157, no public glow setter

`View.AddGlowStyle` in `API.lua` (around line 1493) registers a glow. The menu key is `Plugin:key`, for example `Looks:wick`. `draw(g, at, lo, hi, size)` uses `g:Light`, `g:Trail` and `g:Edge`. `lo` and `hi` are the accent ends. Looks passes those through and does not supply its own colour. `Widgets.lua` `drawAdded` already runs the draw in `pcall` and, on an error, draws Circling from then on. Looks does not catch that error itself.

There is no `SetGlowStyle` on the public API. The writes that pick a glow are private: `DUI:Set("general", "buttonGlow", ...)`, Nameplates `targetLight`, and each Cooldown Manager spell's `glowStyle`. `/looks wick` says to pick Wick in the glow menu. Restore says to pick none there, and still says to pick Daylight in the Frame style menu. Neither writes those settings, and neither touches Palettes or the accent.

`/looks` can still see a glow the player already picked. `API.GetSetting` is read-only (`API.lua` around line 901). Looks reads `general.buttonGlow` (main buttons) and `Nameplates.targetLight` (the target outline). A Cooldown Manager spell can wear a different glow per spell, so the status line does not try to name that pick. When a Looks frame and a Looks glow are both on, the line names the frame and leaves both out of the list. Wick, Draught and Latch each use a 2 second lap, matching the signed-off sheet.

## 2026-11-22 — ODB-159, Trough's power line is not clamped

`View.AddFrameStyle` clamps each size on its own (`API.lua` around line 1460): `height` 6–120, `powerHeight` 1–40. It does not compare them. `PowerBar.LayoutLine` then sets the hung line to `powerHeight` plus its border (`PowerBar.lua` around line 189). A line of 14 can sit under a bar of 11. Trough ships with those sizes on player, target and focus. Party heights stay Daylight's.

A Cooldown Manager glow is not drawn by Looks. Daylight's plugin guide and `API.md` (Glow styles, 1.9) say a plugin glow runs around the spell, a share of the way round its edge. They do not say it sits outside the cooldown swipe and the charge count. `warcraft.wiki.gg`'s [Cooldown](https://warcraft.wiki.gg/wiki/UIOBJECT_Cooldown) widget covers the icon with the swipe, and the [Cooldown Manager](https://warcraft.wiki.gg/wiki/Cooldown_Manager) page does not mention this glow. Daylight's own code does: `CdmEffects.lua` pads the glow 20% past every edge of the spell (`GLOW_PAD`, `sizeGlow`), while `CdmOwn.lua` fills the icon with the swipe and draws the charge count inside that icon. The glow frame is the one that reaches outside.

## 2026-11-22 — ODB-158, applying a look from the page

There is still no `SetFrameStyle` or `SetGlowStyle` on `DaylightUI.API`. Looks tries three routes, and each one is skipped when the function or the key is missing. Chat then gets the old menu line. A missing route does not raise.

1. A public setter, if one shows up later: `view.SetFrameStyle` / `API.SetFrameStyle`, and the same pair for glows.
2. The frame menu's own function. The Frame style dropdown calls `ns.SetStyle` ([Options.lua](https://github.com/dayightt/DaylightUI/blob/main/DaylightUI_UnitFrames/Options.lua#L1557), [Units.lua](https://github.com/dayightt/DaylightUI/blob/main/DaylightUI_UnitFrames/Units.lua#L147)). The unit-frames module holds that `ns` ([Module.lua](https://github.com/dayightt/DaylightUI/blob/main/DaylightUI_UnitFrames/Module.lua#L5)), so Looks calls `GetModule("UnitFrames").ns.SetStyle("look.style", key)` when that function exists and the value sticks. `SetStyle` stores the heights for the new style, then writes through `DUI:Set`.
3. `DaylightUI:Set`, which is the write every other menu uses ([Core.lua](https://github.com/dayightt/DaylightUI/blob/main/Core.lua#L912)). For a frame that is `UnitFrames` / `look.style` (default `"daylight"`, [Defaults.lua](https://github.com/dayightt/DaylightUI/blob/main/DaylightUI_UnitFrames/Defaults.lua#L261)). `OnSettingChanged` runs `Refresh`, which swaps heights again. For a glow the menus are `general` / `buttonGlow` (default `"circle"`, [DB.lua](https://github.com/dayightt/DaylightUI/blob/main/DB.lua#L62), dropdown in [Registry.lua](https://github.com/dayightt/DaylightUI/blob/main/Options/Registry.lua#L1396)) and `Nameplates` / `targetLight` (default `"none"`, [Defaults.lua](https://github.com/dayightt/DaylightUI/blob/main/DaylightUI_Nameplates/Defaults.lua#L28), [Options.lua](https://github.com/dayightt/DaylightUI/blob/main/DaylightUI_Nameplates/Options.lua#L141)). Looks writes both. A Cooldown Manager spell's `glowStyle` is per spell, so a single pick does not walk those rows.

The first time a write sticks, Looks reads those three settings and saves them in `LooksDB` (`## SavedVariables: LooksDB`). A `/reload` still has that snapshot. Restore writes it back and clears it when the frame write and both glow writes stick. A failed write does not save one, and Restore does not take one of its own. If a setting could not be read, or Looks has not changed anything yet, that part of Restore is Daylight's own default: `look.style` = `daylight`, `buttonGlow` = `circle`, `targetLight` = `none`. A glow apply counts only when both `buttonGlow` and `targetLight` stick. If a glow restore fails, the menu line names the saved glow. The saved key for a Looks style is still `Looks:` plus the id. Palettes, the accent, and window tint are not in the allow list. The page is a custom options row because Daylight's standard rows cannot draw the two-column card, the chips, or the icons. The icons are outline strokes. The PRESETS label sits above the preset cards, and the first-login note sits on the Presets & Styles title, right-aligned.
